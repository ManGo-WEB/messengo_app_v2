# Runbook: подключение ВКонтакте (B1)

Статус: **🖥 серверная приёмка** — OAuth-редирект и Callback API требуют публичный
URL; локально канал проверяется интеграционным тестом на фикстурах
(`tests/integration/vk.test.ts`).

## 1. Создание VK-приложения (делает владелец)

1. Открыть [id.vk.ru/apps](https://id.vk.ru/apps) → «Создать приложение».
2. Тип — **Веб-приложение** (VK ID). Название, например, «Messengo».
3. Адрес приложения — домен V2 (прод: `https://messengo.ru`, локально для
   отладки — туннель с публичным URL).
4. После создания скопировать **ID приложения** и **защищённый ключ**
   (Настройки → Ключи доступа).
5. Разрешить ``Разрешить URL для OAuth``: добавить `https://<домен>/api/channels/vk/callback`.

## 2. Переменные окружения

```env
VK_APP_ID=<id приложения>
VK_APP_SECRET=<защищённый ключ>
VK_REDIRECT_URL=https://<домен>/api/channels/vk/callback
VK_WEBHOOK_URL=https://<домен>/api/webhooks/vk
```

## 3. Флоу подключения (что делает оператор в UI)

1. «Подключить ВКонтакте» → сервер формирует ссылку **id.vk.ru/authorize** с PKCE
   (state+verifier связаны HttpOnly-печенькой на 10 минут).
2. Оператор разрешает доступ → возврат на `/api/channels/vk/callback`:
   сервер обменивает код на **user-token** и создаёт PENDING-подключение.
3. Список сообществ (`groups.get filter=admin`) → оператор выбирает сообщество.
4. Сервер отдаёт ссылку **oauth.vk.com/authorize** (`group_ids`, scope 266240 —
   сообщения сообщества) → оператор подтверждает.
5. Callback: обмен кода на **токен сообщества**; сервер:
   - проверяет права токена (`groups.getTokenPermissions` → messages);
   - берёт confirmation-строку (`groups.getCallbackConfirmationCode`);
   - генерирует **секрет Callback API** (48 hex-символов) и регистрирует
     Callback-сервер (`groups.addCallbackServer` с `secret_key`);
   - включает `message_new` (`groups.setCallbackSettings`, API 5.199);
   - подключение → **ACTIVE**; в config (зашифровано): groupId, токен,
     confirmation, секрет; опционально `senderName` — имя оператора в исходящих.
6. VK присылает `confirmation`-событие на вебхук — сервер отвечает
   confirmation-строкой, после чего Callback-сервер становится «подтверждён»
   на стороне VK.

## 4. Проверка после подключения

- `POST /api/webhooks/vk` c `type=confirmation` отвечает строкой confirmation;
- написать в сообщения сообщества — в Inbox появляется диалог;
- ответ оператора уходит `messages.send` (SendAttempt = SENT).

## 5. Ограничения и заметки

- Проверка вебхука — сравнение `secret` в payload с сохранённым секретом
  (timing-safe) + совпадение `group_id` (механика V1; md5-подпись VK не
  используется).
- У оператора должны быть права администратора сообщества — проверяется
  при выборе сообщества и повторно в callback.
- Обновление токена сообщества — повторное подключение того же сообщества
  (создаётся новое подключение; старое отключить в B5).
