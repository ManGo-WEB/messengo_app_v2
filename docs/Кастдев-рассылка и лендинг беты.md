# Кастдев-рассылка и лендинг беты — концепция

> **Статус:** согласовано 2026-11-09. Реализация не начата: лендинг не собран, amoCRM-интеграция не настроена, рассылка не отправлялась.

## 1. Цель кампании

- Проверить спрос на Messengo до доработки v2, **до** того как дописана функциональность.
- Приоритизировать фичи v2 по реальным болям (фичи маппим сами по ответам, не спрашиваем «какие фичи нужны»).
- Набрать круг первых бета-тестеров.
- База: ~400 кандидатов в Google-таблице; у каждой строки контакта — свой ID.

## 2. Воронка

Гибридная, по теплу сегмента:

| Сегмент | Путь |
|---|---|
| Массовый (~остальные) | сообщение/email со ссылкой → лендинг `messengo.ru/beta/?id=NN` → квиз на самой странице |
| Самый тёплый (5–15 чел.) | личное сообщение со ссылкой сразу |
| Полутёплые | сначала короткое сообщение **без** ссылки («Можно 5 минут твоего внимания?»), ссылка — после ответа |

Отправка волнами по 10–15 человек; после каждой волны правим формулировки по первым ответам.

Метрики воронки (Яндекс.Метрика): клик в сообщении → открыл лендинг → начал квиз → **reachGoal на каждом шаге квиза (шаг1…шаг7 — увидим, на каком вопросе отваливаются)** → отправил анкету (`form_sent`) → спасибо-страница (цель по pageview).

## 3. Сквозной ID и трекинг

- У каждого контакта в Google-таблице — ID из его строки.
- ID подставляется в ссылку рассылки: `messengo.ru/beta/?id=NN` + UTM-метка канала.
- Квиз отправляет ID скрытым полем вместе с ответами — сначала в прокси-скрипт, далее в лид amoCRM.
- Связка «ответ ↔ контакт» — по столбцу ID в той же таблице.
- Видимое поле «Код (не менять)» из раннего плана (Google-формы) больше не нужно — форма своя (решение 09.11 вечера).

## 4. Каналы и сервисы

- **Тёплый сегмент** — личные мессенджеры, персональное сообщение (не бот).
- **Остальные** — email через сервис рассылки **Coldy** (регистрация 09.11).
- **CRM** — **amoCRM**: решение владельца — все коммуникации с клиентами и потенциальными клиентами проходят через amoCRM. Аккаунт планируется запросить бесплатно через партнёрскую программу; если не выйдет — минимальный тариф.

## 6. Анкета-квиз: 7 вопросов

Принципы: минимум ввода, чекбоксы, свободное поле только в «Прочее», обязательные 2–3 вопроса. В формулировках **нет** слова «Messengo» и названий фич из плана — чтобы не подтверждать наши догадки.

1. **В каких каналах вы общаетесь с клиентами?** (чекбоксы, обязательный): Telegram / WhatsApp / MAX / Instagram Direct / ВКонтакте / Авито / Телефон, SMS / Email / Другое: ___

6. **Что из этого было бы для вас самым ценным? ## 7. Лендинг `messengo.ru/beta`

Требования: mobile-first (весь трафик из мессенджеров; кнопка видна без скролла на телефоне), визуальный стиль прототипа v2 (`design/prototype`), статичный HTML+JS без библиотек и сборщиков. Страница принимает `?id=NN`.

### Блок 1 — герой (финал после рефрейма 09.11)

> **Заголовок:**
> Клиенты пишут в Telegram, MAX и Instagram — а вы разрываетесь между пятью приложениями?
>
> **Подзаголовок:**
> Мы делаем сервис, который соберёт их все в одно окно. Его ещё нет — и прежде чем дописывать код, мы хотим понять, как с клиентскими сообщениями работают люди вроде вас.
>
> **Строка над кнопкой:**
> Помогите решить, что строить первым.
>
> **Кнопка:** Ответить на 7 вопросов
>
> **Подпись под кнопкой (мелким):** 5 минут · всё кликами

Логика рефрейма: заголовок-боль сохранён (фильтрует аудиторию, не продаёт); честное «его ещё нет» стоит сразу на первом экране, а не в блоке 4; CTA «Помогите решить, что строить первым» — эхо темы email, воронка читается как одно непрерывное предложение; счётчик вопросов и время — у кнопки.

### Блок 2 — три карточки боли

Заголовки карточек — сокращённые формулировки вариантов вопроса 3 анкеты (правило: боль на лендинге и варианты в анкете должны совпадать; при сборке выверить дословность).

> **1. Постоянно переключаюсь между приложениями**
> Личный чат, рабочие чаты и почта в разных окнах — сообщение теряется в потоке уведомлений.
>
> **2. Отвечаю с опозданием, и клиент уходит**
> Пока увидел сообщение среди личных чатов, клиент уже написал конкуренту.
>
> **3. Не помню, кто и что обещал**
> История общения с клиентом размазана по трём мессенджерам — вечером не собрать, о чём договорились.

В анкете (вопрос 3) к ним добавляются: «Приходится отвечать в нерабочее время» и контрольное «С сообщениями всё в порядке».

## 8. Техническая архитектура отправки

Форма — полностью своя (квиз на странице), не Google-форма. Данные уходят в amoCRM.

```
messengo.ru/beta/?id=NN
   ↓ JS читает ?id=NN (+ UTM)
   ↓ лендинг → кнопка → скролл к квизу (7 шагов, прогресс-бар, валидация на своей стороне)
   ↓ POST JSON {id, utm, ответы, honeypot}
   ↓ PHP-прокси на том же хостинге Beget (~50 строк): антиспам → лид в amoCRM
   ↓ ответ {ok:true} → редирект /beta/spasibo/?id=NN
   ↓ Метрика: pageview спасибо-страницы (цель) + reachGoal('form_sent') в момент успеха
```

- Прямая отправка из статичной страницы в amoCRM API невозможна безопасно (токен был бы виден в исходнике) — поэтому посредник.
- Прокси — PHP на Beget (поддержку PHP на тарифе проверить, когда восстановится личный кабинет). Запасной вариант: внешний коннектор (Albato/Salebot) — для кода лендинга разницы нет, адрес приёма это одна константа.
- Пока хостинг недоступен — локальная сборка с **мок-режимом** отправки (лог/консоль); боевой endpoint подменяется одной строкой в конфиге.
- Предложенная структура лида: одна анкета = один лид «Кастдев-анкета #ID», ответы в описании/полях, ID — сквозной из Google-таблицы; контакт из таблицы привязывается вручную.
