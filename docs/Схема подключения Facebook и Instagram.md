### 🗺️ Общая архитектура системы

Ваше приложение будет выступать в роли **посредника (Middleman)** между интерфейсом пользователя (ваш личный кабинет) и серверами Meta.

```
[Пользователь A] ──Facebook Login──► [Ваше Приложение (Backend)]
```

Схема состоит из трех ключевых контуров: **авторизация**, **получение событий (Webhooks)** и **отправка ответов**.

### 🔑 Контур 1: Авторизация и привязка аккаунтов (Facebook Login)

Поскольку в приложении будет несколько пользователей, каждый из них должен независимо пройти процедуру входа и предоставить вашему приложению права на управление своими аккаунтами.

1. **Создание приложения в Meta for Developers**: Вы создаете приложение типа **Business** в панели разработчика Meta и добавляете в него продукты **Facebook Login** и **Messenger** (с настройками для Instagram).
2. **Вход пользователя (OAuth 2.0)**: В вашем приложении каждый пользователь нажимает кнопку «Войти через Facebook». Открывается стандартное окно авторизации Facebook.
3. **Запрос разрешений (Permissions)**: При входе ваше приложение запрашивает у пользователя набор разрешений (scopes), необходимых для работы:
   - `instagram_basic` — для доступа к базовой информации об аккаунте.
   - `instagram_manage_messages` — для чтения и отправки сообщений в Direct.
   - `instagram_manage_comments` — для чтения и модерации комментариев.
   - `pages_manage_metadata` — для управления подписками на события (webhooks).
   - `pages_messaging` — для работы с сообщениями Facebook Messenger (если нужно).
4. **Получение токена пользователя**: После подтверждения пользователь получает **User Access Token**. Ваш бэкенд должен безопасно сохранить этот токен в базе данных, привязав его к конкретному пользователю вашей системы.
5. **Получение Page Access Token (Критически важный шаг)**: Токен пользователя сам по себе не дает доступа к сообщениям. Используя User Access Token, ваш бэкенд запрашивает у Graph API список Facebook-страниц, которыми управляет пользователь (эндпоинт `/me/accounts`). Для каждой нужной страницы вы получаете **Page Access Token**. Именно этот токен (а не токен пользователя) в дальнейшем используется для чтения и отправки сообщений от имени страницы/Instagram-аккаунта.
6. **Привязка Instagram**: Instagram-аккаунт пользователя должен быть **профессиональным (Business/Creator)** и связан с той самой Facebook-страницей, доступ к которой вы получили. Без этой связи Instagram API не сможет получить доступ к сообщениям и комментариям.

> **Важно для мультиаккаунтности**: В отличие от некоторых SDK, где одновременно активен только один пользователь, на уровне серверной архитектуры вы можете хранить неограниченное количество токенов (User и Page) в своей базе данных, каждое со своей привязкой к вашему пользователю. Ваш Inbox будет работать с тем набором токенов, который соответствует выбранному в интерфейсе аккаунту.

### 📡 Контур 2: Получение сообщений и комментариев (Webhooks)

Чтобы ваше приложение «узнавало» о новых сообщениях и комментариях в реальном времени, используется механизм **Webhooks**. Вместо постоянного опроса (polling), Meta сама отправляет HTTP-запрос на ваш сервер, когда происходит событие.

1. **Создание Webhook-эндпоинта**: На вашем сервере (backend) создается публичный HTTPS-адрес (например, `https://your-app.com/webhook`), который умеет принимать POST-запросы.
2. **Верификация**: При первой настройке Meta отправляет GET-запрос на ваш эндпоинт для проверки. Ваш сервер должен корректно на него ответить, подтвердив владение.
3. **Подписка на события (Subscription)**: В панели разработчика Meta (или через API) вы подписываете ваше приложение на конкретные типы событий для каждой подключенной страницы:
   - Для **Instagram Direct**: подписка на поле `messages`.
   - Для **Instagram комментариев**: подписка на поле `comments` (и `live_comments`, если нужно).
   - Для **Facebook Messenger**: подписка на соответствующие поля сообщений.
4. **Обработка входящего события**: Когда пользователь пишет в Direct или комментирует пост, Meta отправляет JSON-объект на ваш Webhook. Этот объект содержит:
   - ID отправителя (Instagram-scoped ID).
   - Текст сообщения или комментария.
   - ID медиа (поста), если это комментарий.
   - **Важно**: Ваш сервер должен отвечать статусом `200 OK` в течение 5 секунд, иначе Meta может повторить отправку.
5. **Маршрутизация**: Ваш бэкенд, получив событие, определяет, какому из ваших пользователей (и какому именно аккаунту) оно принадлежит (по ID страницы/аккаунта в событии), и сохраняет его в базу данных. После этого сообщение мгновенно отображается в интерфейсе Inbox нужного пользователя.

### ✉️ Контур 3: Отправка ответов (Send API)

Когда пользователь вашего приложения пишет ответ в интерфейсе Inbox, ваш бэкенд выполняет обратный вызов к API Meta.

1. **Выбор правильного токена**: Бэкенд берет сохраненный **Page Access Token**, соответствующий тому аккаунту, от имени которого нужно отправить сообщение.
2. **Отправка сообщения (Direct)**: Выполняется POST-запрос к эндпоинту `/<PAGE_ID>/messages` (или `/<IG_ID>/messages`) с указанием получателя (Instagram-scoped ID) и текста сообщения.
3. **Ответ на комментарий (Private Reply)**: Для ответа на комментарий в Direct используется специальный эндпоинт, где в параметре `recipient` указывается `comment_id`. Это позволяет отправить человеку личное сообщение в ответ на его публичный комментарий.
4. **Модерация комментариев**: Если ваша цель — не только отвечать в Direct, но и управлять комментариями (скрывать, удалять, отвечать публично), используются соответствующие эндпоинты `instagram_manage_comments` (например, для публичного ответа или скрытия комментария).

### ⚠️ Ключевые ограничения и требования, которые влияют на схему

1. **Advanced Access (Расширенный доступ)**: Это **самый важный** пункт для вашего сценария. Поскольку ваше приложение будет обслуживать **других пользователей** (не только вас), вам потребуется пройти **App Review** в Meta и получить **Advanced Access** для разрешений `instagram_manage_messages` и `instagram_manage_comments`. Со «Стандартным доступом» приложение будет работать только для аккаунтов, которыми владеете вы или ваши тестировщики. Процесс ревью может занять недели.
2. **Окно ответа (24 часа)**: Вы можете отправлять сообщения в Instagram Direct только в течение **24 часов** с момента последнего сообщения от пользователя. Для комментариев правило другое: частный ответ (Private Reply) можно отправить в течение **7 дней** с момента комментария, но только один раз.
3. **Требования к аккаунтам**: Все Instagram-аккаунты, с которыми будет работать ваше приложение, должны быть **профессиональными** и привязаны к Facebook-страницам.
